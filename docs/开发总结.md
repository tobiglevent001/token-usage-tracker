## 一、项目背景

### 需求来源

用户使用多个 AI 平台（DeepSeek、Kimi、OpenAI 等），需要：
1. 统一查看各平台的账户余额
2. 自动生成每日余额报告
3.追踪消耗趋势
4. 配置多个平台的 API Key

### 痛点

- 各平台余额查询方式不同，需要分别登录查看
- 无法统一汇总和对比
- 手动记录消耗趋势太麻烦

## 二、开发过程

### Phase 1：需求调研与 API 调研（2小时）

| 平台 | 余额 API | 结果 |
|------|---------|------|

**调研报告**：`references/api_balance_research.md`

---

### Phase 2：配置界面开发（3小时）

#### 问题1：前端静态数据无法加载

用户反馈页面打开后"全部都是静态的，不能用"。

**根因分析**：
- 前端 JavaScript 的 `fetch('/api/models')` 依赖服务器 API
- API 调用失败后页面数据全空

**解决方案**：
- 重写前端为独立页面（模型数据内嵌）
- 支持 localStorage + Flask 双模式
- 测试连接功能实际调用 API

#### 问题2：Flask 服务器不稳定

**根因分析**：
- `debug=True` 导致服务器自动重启
- Flask 未正确安装到系统 Python

**解决方案**：
- `debug=False` 稳定运行
- `pip install flask` 安装到正确路径

---

### Phase 3：核心功能开发（2小时）

#### 余额抓取模块（`fetch_usage.py`）

实现 `BalanceFetcher` 类：
- 支持DeepSeek、Kimi/Moonshot 余额 API
- 从 `auth.json` 或环境变量读取 API Key
- 解析 JSON 响应，提取余额数据

#### 报告生成模块（`generate_report.py`）

实现 `ReportGenerator` 类：
- 从真实余额数据生成 Markdown 报告
- 支持历史数据趋势分析
- 双语输出（中文 + 英文）

#### 统一入口脚本（`run.py`）

一条命令完成全流程：
```bash
python scripts/run.py --platforms deepseek --lang zh
```

## 四、技术亮点

### 1. 独立前端设计

配置界面支持两种模式：
- **离线模式**：localStorage 存储，无需服务器
- **在线模式**：Flask 服务器，同步到 JSON 文件

### 2. 实际 API 测试

测试连接功能真正调用 AI API，返回真实错误信息（401/429/403），不再只检查格式。

### 3. 统一接口设计

`BalanceFetcher` 类支持扩展新平台：
```python
BALANCE_APIS = {
    "deepseek": {...},
    "moonshot": {...},
    # 新平台直接添加即可
}
```

## 七、经验总结

### 开发教训

1. **前端不应完全依赖 API** — 离线模式下数据应内嵌
2. **Flask debug=True 不稳定** — 生产环境用 debug=False
3. **pip install --target 路径问题** — 应安装到系统 Python

### 最佳实践

1. **调研先行** — 先确认 API 可用性再开发
2. **增量测试** — 每个模块完成后立即测试
3. **真实数据验证** — 用真实 API Key 验证功能
